1. Session Overview

This session focused on two major enhancements to the ISR Mission Planner:

  1. Map Integration - Added a Leaflet map underlay with Grid/Map toggle, allowing missions to be visualized on real geographic coordinates
  2. Stats Consistency Fix - Fixed a bug where animation stats showed different fuel values than solver stats

Additionally, we documented the relationship between grid units and real-world distances for mission planning reference.

2. Map Integration (Leaflet)

What Was Added

The ISR Planner now supports a real geographic map underlay using Leaflet.js, enabling missions to be planned on actual terrain.

Features

  • Grid/Map Toggle - Buttons in canvas header to switch between abstract grid view and map view
  • Tile Layer Selection - Street map or Satellite imagery options
  • Geographic Pinning - All elements (targets, airports, SAMs, trajectories) are pinned to lat/lng coordinates
  • Pan Support - Drag to pan when not in edit mode
  • Edit Mode - Canvas captures clicks for placing elements
  • Coordinate Transformation - Seamless conversion between grid coordinates and geographic coordinates

Technical Implementation

ComponentDescription
w2c()World-to-canvas conversion using Leaflet's latLngToContainerPoint in map mode
canvasToWorld()Canvas-to-world conversion using Leaflet's containerPointToLatLng in map mode
gridToLatLng()Converts grid coordinates (0-100) to lat/lng within configured bounds
latLngToGrid()Converts lat/lng back to grid coordinates

Default Geographic Bounds

The default map area is centered on San Francisco:

{
  south: 37.70,
  north: 37.85,
  west: -122.51,
  east: -122.36
}

This 0.15° × 0.15° area maps to the 100 × 100 grid coordinate system.

3. Animation Stats Fix

Problem Statement

The mission stats panel showed different values after animation compared to after accepting a solve:

MetricAfter SolveAfter Animate
D3 Fuel207 / 250283 / 250 (OVER!)
Total Fuel1051 / 12151849 / 1215

This caused confusion because D3 appeared within budget after solve but over budget after animation.

Root Cause Analysis

Two Different Distance Calculations

The application had two functions calculating stats:

  1. updateStatsFromRoutes() - Used after accepting a solve
    • Uses routeInfo.distance (solver's computed value)
    • Includes SAM-aware shortest path distances + loiter fuel
  2. updateStatsFromAnimation() - Used during/after animation
    • Was using droneState.distanceTraveled (trajectory-based)
    • Calculated by walking through all trajectory points

Why They Differed

Solver Distance = Matrix-based shortest paths + loiter fuel
Animation Distance = Sum of all trajectory segment lengths

The trajectory includes many intermediate points for smooth SAM avoidance, making the animation distance artificially longer than the solver's actual fuel cost.

Solution

Modified updateStatsFromAnimation() to use routeInfo.distance (the solver's value) instead of droneState.distanceTraveled:

// Before (incorrect)
const distanceTraveled = droneState.distanceTraveled;
setText(`stat-d${did}-fuel`, `${Math.round(distanceTraveled)} / ${Math.round(budget)}`);

// After (correct)
const routeDistanceForDisplay = Number(routeInfo.distance || 0);
setText(`stat-d${did}-fuel`, `${Math.round(routeDistanceForDisplay)} / ${Math.round(budget)}`);

Result

MetricAfter SolveAfter Animate
D3 Fuel207 / 250207 / 250 ✓
Total Fuel1051 / 12151051 / 1215 ✓

4. Map View Export/Import

When exporting an environment JSON, the current map view is now saved:

{
  "map_view": {
    "bounds": { "south": 37.70, "north": 37.85, "west": -122.51, "east": -122.36 },
    "center": { "lat": 37.775, "lng": -122.435 },
    "zoom": 13
  }
}

When importing, restoreMapView() restores the geographic area so users see the same map location as when the environment was saved.

5. Grid Distance & Drone Speed Reference

Grid-to-Real-World Distance

The coordinate system maps geographic coordinates to a 100×100 grid:

ParameterValue
Default bounds0.15° latitude × 0.15° longitude
Grid size100 × 100 units
1 grid unit (N-S direction)~166.5 meters
1 grid unit (E-W direction)~132 meters (at lat ~37.77°)
Average~150 meters per grid unit

How It's Calculated

Latitude:  1° ≈ 111 km
           0.15° ≈ 16.65 km
           100 units = 16,650m → 166.5 m/unit

Longitude: 1° ≈ 111 km × cos(37.77°) ≈ 88 km
           0.15° ≈ 13.2 km
           100 units = 13,200m → 132 m/unit

Average: (166.5 + 132) / 2 ≈ 150 m/unit

Drone Speed

When drone speed is set to 1:

  • Drone travels 1 grid unit per time unit
  • This equals approximately 150 meters per time unit

Fuel Budget Interpretation

Since fuel is measured in grid units of distance:

Fuel BudgetApproximate Range
100 units~15 km
150 units~22.5 km
200 units~30 km
250 units~37.5 km
300 units~45 km

Practical Example

A drone with fuel budget = 150:

  • Can travel approximately 22.5 km total distance
  • At speed = 1, this takes 150 time units
  • Must return to an airport before exhausting fuel
  • With a round-trip mission, effective radius is ~11 km from start airport
